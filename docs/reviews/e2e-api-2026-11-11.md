# End-to-end API check — 2026-11-11

Scope: the real `build/backend/hnswhy_server` binary, a fresh temporary
SQLite database, the bundled sample knowledge base, and the real benchmark
report. This checks the HTTP surface and restart behaviour; the frontend is
covered separately.

## Setup

```bash
./build/backend/hnswhy_server \
  --db /tmp/opencode/hnswhy-e2e/main.db \
  --port 8091 \
  --samples-dir samples
```

Fresh database, default hash embeddings (`local-hash-v1`, 256d) and
extractive chat (`local-extractive-v1`).

## Observations

- Startup rebuild from SQLite is clean: the restarted process reported
  17 live vectors, 17 slots and zero tombstones, not the pre-restart
  tombstone count.
- The first restart check was invalid because the old server process was
  still bound to the same port alongside the new one. The test harness now
  uses one process; this was a test setup mistake, not a product defect.
- The frontend was served by the backend, but browser-level visual and
  keyboard checks were not performed in this run. That gap is now closed by
  `scripts/e2e/ui-e2e.cjs`; see `docs/reviews/e2e-2026-11-11.md`.
